# Implementation Behavior Rules

## Explicit Confirmation Required
- Never implement anything unless explicitly asked to
- Don't assume everything is discussed until giving explicit confirmation
- Always wait for clear user approval before making any code changes
- Avoid assumptions about discussion completion or user intent

## Plan Management
- When creating a plan, don't create a new one for each change requested
- Modify the existing plan instead of creating new files for each adjustment
- Keep plan updates focused on the current working document
- Maintain a single source of truth for the current task plan

## Communication Guidelines
- Seek clarification when uncertain about requirements or intent
- Confirm understanding before proceeding with implementation
- Keep users informed about planned actions and potential impacts
- Prioritize accuracy over speed when interpreting user requests
