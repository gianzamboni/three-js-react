# Development Workflow Rules

## Planning Process
- When making a plan, design each step so it is **self-contained and testable**
- No step should depend on unfinished later work for verification
- Break down complex tasks into manageable, verifiable steps

## Implementation Approach
- Implement **one** step, then **pause** and wait for feedback on that step's changes
- Continue only after approval: Do not move to the next step until the user is happy with the current step and explicitly gives the green light to continue (e.g. "looks good", "continue", "next")
- Focus on minimal, testable changes that can be verified independently

## Quality Assurance
- Ensure each implemented step can be tested and verified before proceeding
- Maintain clear communication about progress and blockers
- Keep implementation focused and avoid scope creep during execution
